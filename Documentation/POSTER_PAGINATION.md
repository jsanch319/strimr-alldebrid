# Swipe-only poster pagination

On iOS, the shared movie/TV carousels retain their original native swipe behavior with no visible Previous/Next arrows, custom scroll-position binding or programmatic paging animation. Each scroll view retains its own position. Appending stable title IDs does not replace the rail or reset its scroll position. Horizontal intent and near-end visibility trigger one pending prefetch per row; vertical scrolling does not intentionally activate another row. A small spinner indicates a pending page; errors retain existing posters and expose Retry. Native VoiceOver scrolling remains available, with a nonvisual Load More action. Existing Reduce Motion behavior is preserved. The finite streaming-service card strip also has no iOS arrow overlays or decorative navigation arrow. Back, Close, See All and other controls outside horizontal content remain available.

TMDb Trending, Popular, Upcoming, Top Rated and title recommendations use API page metadata, append unique movie/TV identities, and stop at the advertised end (maximum 500, TMDb's API ceiling). Home, Movies and TV Shows share cached feed contents while each rendered rail retains independent scroll state. Each distinct feed and recommendation request stream has its own page/loading/error state. Personalized recommendations use the account's actual history seeds. Refresh/account changes reject stale requests. Concurrent edge signals cannot issue the same page twice; error states stop automatic retries, and rate-limit deadlines block early retries. Merely opening a horizontal row does not crawl the catalog: loading starts when the user advances or swipes near its end.

Provider Discover Movies/TV grids and Search/See All grids append automatically near their last visible items and retain explicit Load More/Retry actions. Provider filters reset only the affected catalog. Search uses a generation token to reject stale responses, including repeated identical queries. Grid identity no longer changes whenever a search page is appended.

Server-backed Home, library-recommended and related hub rails reuse the existing HubDetailViewModel and provider paging service. Initial posters seed that pager; appending keeps their stable IDs and advances by the number of records returned, even when a page contains duplicates. Only hubs explicitly advertising more items with a valid provider endpoint are queried. Seerr discovery's five movie/TV/trending rows have independent API page cursors as well. Already loaded finite collections and merged rows without a single provider paging endpoint stop at their real end; opening their existing destination remains available.

Simkl Continue Watching, Next Episodes and My List use the complete lists already fetched by the existing synchronization API. No unsupported page/offset parameters or synthetic items are added. Local unfinished progress remains included. Artwork selection, card styling, progress bars, native navigation and player/resume/tracking code are unchanged.

Tests cover stable append/deduplication, API exhaustion, overlapping requests, refresh conflicts, independent row cursors and rate-limit backoff. The isolated iPhone simulator fixture supplies two real-title pages (with an intentional overlapping title) only for its pagination interaction test. It tests the absence of row arrows, swipe-based loading, stable deduplication, independent neighboring-row position and return to original posters. API exhaustion is verified by unit tests. This is not a live-account or physical-device performance test. VoiceOver usability, Dynamic Type, smaller devices, Reduce Motion perception, live accounts and extremely long browsing sessions still need device review.
