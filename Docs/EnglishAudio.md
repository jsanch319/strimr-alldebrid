# English audio and iPhone hero sizing

On iPhone, open **Settings → Playback → Audio → Always Prefer English Audio** (on by default). Existing installations migrate to on; switching it off persists. The existing Settings → Audio shortcut opens the same preferences.

The original player asks the engine for English (`en`/`eng`) at load, then uses actual audio-track language tags, including regional forms such as `en-US`, to select the best English track. Main audio ranks above commentary and description according to track flags/titles. File names, Torrentio MULTI labels and display names never prove a language. Missing/undetermined language tags remain unknown. No dub is synthesized. Unmarked commentary/description cannot be reliably distinguished.

The native controls have a labeled Audio & Subtitles button. Manual choices override automatic English selection for the current title (including automatic source fallback) and cancel any language-source check; Reset Track Selections restores automatic preference. Late track metadata is handled without repeatedly forcing the same selection. Remote HLS uses AVFoundation's real media-selection options instead of FFmpeg stream indices. Normal engine routes retain their existing track switching. Media-server transcoding can request a session-only English preference without overwriting saved per-title defaults.

If English is known to be absent, automatic catalog playback may inspect up to three other **ready** matching magnet files or direct add-on sources while the current video continues. AVFoundation must positively confirm playable, unprotected audio with English metadata before replacement; inspection never uploads a magnet or acquires another file. Each asset's metadata load is canceled after six seconds or on task cancellation. Current exact position is saved and passed explicitly to the replacement using the existing resume/Simkl player flow. Manual selection, pausing, scrubbing, track-menu interaction, backgrounding, PiP/AirPlay, SharePlay, account/configuration changes or a stale media identity prevent replacement. If no source can be verified, playback continues and a notice appears in feedback and the track menu.

This is intentionally conservative: AVFoundation cannot prove English for many MKV/custom/FFmpeg-only sources, missing language metadata, header-dependent assets, or unsupported codecs. Those sources are not automatically selected by language; the current stream stays available for manual track selection. Confirmed metadata is not a guarantee against incorrectly tagged content.

The iPhone Home hero targets **70% of its available viewport**. Very short landscape viewports use a 200-point readability floor, capped at available height; compact title/actions preserve access. Artwork, logos, gradients, controls, trailer readiness/fades, mute state, and native scrolling stay in the original components. iPad/macOS/tvOS hero sizing keeps its existing rules. Existing authorized-trailer provider limitations remain unchanged.

## Verification limits

Unit tests cover language tags, main/commentary/description ranking, opt-out migration, manual overrides, late metadata, bounded/confirmed source replacement, cancellation and phone geometry. CI uses synthetic source/track metadata and tiny generated silent MP4 files with real `fra`/`eng` track tags, not personal add-on credentials or real movie playback. Saved hoster links, unknown language tags, and sources requiring processing are not acquired just to inspect a language. Signed-iPhone testing should cover multilingual MP4/MKV/HLS, delayed track lists, commentary/description flags, manual changes during source inspection, exact resume after replacement, Simkl, background/lock/AirPlay, and smaller-phone/landscape text/buttons and trailer mute behavior. Device/receiving-route codec and track-selection limitations still apply.
